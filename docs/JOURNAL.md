## Step 0 · Set up the workshop — 2026-10-26
- Built: ADR template + ADRs 0001 (stack) and 0002 (RahulCoolGram), this journal, first PR merged on GitHub.
- Broke / surprised me: branch protection needs a paid plan for private repos, so the "PR + green CI" rule is a habit, not enforced.
- Learned: an ADR records *why* we chose something and what we rejected. Queues: RabbitMQ is a separate broker; Procrastinate keeps jobs in Postgres, so saving data and queueing a job is one transaction (no dual-write problem, no outbox needed).
- Next time I would: skip things that don't help yet (project board) and get to code sooner.

## Step 1 · API skeleton — 2026-10-26
- Built: `core/config.py` with pydantic-settings, `/health` test, ruff, and a CI workflow for `apps/api`. Renamed `apps/simulator` to `apps/rahulcoolgram`.
- Broke / surprised me: `from .main import app` in the test failed with "attempted relative import with no known parent package". Also, pytest fails when there are no tests, so CI must be added together with the first test.
- Learned: Python finds imports by searching the folders in `sys.path`. Our root is `apps/api`, so imports are absolute from there (`from core.config import settings`), never relative. Settings come from environment variables, so the same code runs everywhere (`APP_NAME=... ` changed the title).
- Next time I would: say the import path out loud from the root before typing it.

## Step 2 · In-memory inbox — 2026-10-26
- Built: `GET /conversations`, `GET` + `POST /conversations/{id}/messages` on Python dicts; one error shape (`{"error": {"code", "message"}}`); a request id on every request and JSON log lines. 17 tests.
- Broke / surprised me: `Annotated(...)` instead of `Annotated[...]` (round vs square brackets). A route path repeated the router prefix (`/conversations/conversations/...`). Two 404 tests "passed" before the routes existed, because every unknown URL is a 404.
- Learned: tests written first act as the spec. The server decides `sender_type` and `direction`, never the client. Renamed `user` → `staff` because "user" was ambiguous. Restarting the server loses all messages: that's why step 3 adds Postgres.
- Changed: replaced my hand-written stdlib JSON logging (ContextVar + filter + formatter) with loguru: `logger.contextualize(request_id=...)` does the same in a few lines.
- Next time I would: watch a new test fail for the right reason before trusting it.

## Steps 3–5 · Postgres, ORM, migrations, seed — 2026-10-26
- Built: Postgres 18 in Docker Compose; SQLAlchemy 2 async models (organizations, contacts, conversations, messages) with `org_id` everywhere and CHECK constraints; first Alembic migration; routes → service split; `seed.py`; `/health/live` + `/health/ready`. Tests run on a real `inbox_test` DB; CI runs `alembic check`.
- Broke / surprised me: in zsh, `! cmd` means "not", so `! sudo systemctl ... && docker compose up` skipped the second command. Autogenerated constraints had no names until I added a naming convention. Pooled DB connections broke across pytest's event loops → NullPool in tests.
- Learned: UUIDv7 ids are time-ordered (better for indexes than v4). The sender type comes from which code path a message enters through, never from the request body. Skipped the in-memory store: build the real thing directly.
- Next time I would: set the constraint naming convention before generating the first migration.
